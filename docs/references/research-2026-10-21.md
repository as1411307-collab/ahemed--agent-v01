## ب) أدوات ومكتبات جاهزة للواجهة (مب سكلز)

- **LiveKit Agents UI** (registry لـ shadcn): `npx shadcn@latest registry add @agents-ui` ثم `npx shadcn@latest add @agents-ui/all`. مكونات: AgentControlBar، AgentChatTranscript، AgentChatIndicator، و**خمس مرئيات صوت**: Bar، Grid، Radial، Wave، **Aura**. مع تطبيق البداية `livekit-examples/agent-starter-react`. هذا جاهز لوضع الصوت لما يجي وقته.
- **AG-UI protocol** (ag-ui-protocol/ag-ui، مع CopilotKit): بروتوكول مفتوح لبث أحداث الوكيل إلى الواجهة (نص، نداءات أدوات، حالة، موافقة بشرية) — معيار جاهز لـ"جدول الحدث → شو يصير في الواجهة" بدل ما نخترع صيغة أحداث.
- **Theatre.js** (إخراج الكاميرا والحركة على خط زمني)، **Lenis** (سكرول ناعم)، **Howler** (صوت)، **postprocessing** (bloom/godrays/DoF)، **Rapier** (فيزياء) — كلها تظهر في السكلز أعلاه.
- **ThreeUI**، **React Bits**، **thinking-orbs**، **Lucide**: مسجّلة في `docs/SKILLS.md` من مراجع 13 أكتوبر.

## ج) أدوات جانب الوكيل واللوحة الحية

- **hoangsonww/Claude-Code-Agent-Monitor** (MIT): لوحة مراقبة حية لـ Claude Code وCodex عبر hooks → Express + SQLite → WebSockets. فيها: لوحة صحة، Kanban، خط زمني للجلسات، تحليلات (رموز، أدوات، خريطة حرارية)، و**صفحة Workflows فيها DAG لتنسيق الوكلاء ورسوم Sankey**. تطبيق سطح مكتب Electron وإضافة VS Code وMCP server. مرجع مباشر لـ"الرسم الحي ببيانات حقيقية"، ومصدر أحداث جاهز لو الوكيل يشتغل من Claude Code.
- **Langfuse trace graph view** (يوليو 2026): وضعان — Aggregated (العقد المتكررة تنطوي بعدّاد والحلقات دوائر) وExpanded (كل نداء عقدة، الحلقات تنفرد بترتيب التنفيذ). نفس الفكرة اللي نبيها للوحة: خطوات = عقد، انتقالات = خطوط.
- **Mission Control** (MeisnerDan، dev.to): مدير مهام لمن يفوّض الشغل لوكلاء Claude Code (3–4 وكلاء). ملفات JSON بدل قاعدة بيانات مع قفل لكل ملف، daemon يشغّل `claude -p` بشخصيات، كشف الحلقات (تصعيد للإنسان بعد 3 محاولات فاشلة)، حد توازي 3، 25 دور، مهلة 30 دقيقة، جدولة يومية/أسبوعية. درس التكلفة: تفريغ ملف المهام كله في السياق = ~5,400 رمز لـ50 مهمة؛ استعلامات مفلترة = ~50 رمز (أقل 92%).
- **Shafaiel/mission-control**: لوحة React + Express مع وكيل (Groq) يدير المهام بأدوات بأسلوب MCP (`tools/list`، `tools/call`). بسيط، مرجع هيكل.
- **winfunc/opcode** (AGPL-3.0، Tauri + React): واجهة سطح مكتب لـ Claude Code: الجلسات، وكلاء مخصصون بخلفية، لوحة استخدام وتكلفة، نقاط حفظ وخط زمني وتفرّع. مرجع لشاشة "الاستخدام والتكلفة".

## د) تجارب الناس (وش اشتغل ووش لا)

1. **اختبار 9 سكلز واجهة** (Medium، 2026): `frontend-design` غيّر الناتج "كأنه موديل ثاني"؛ UI UX Pro Max حدد الأسلوب والألوان والخطوط قبل أي مكوّن؛ Taste Skill أقوى شي فيه تدقيق إعادة التصميم ("قال لي وش يخلي الواجهة تبين رخيصة وصلّحه قسم قسم")؛ Impeccable يشتغل كمصمم بقائمة فحص (critique ثم polish)؛ Emil's skills صلّحت الـeasing والتقطيع؛ Interface Design خلّى صفحات لوحة بُنيت على أسبوع متسقة ("بدونه كل صفحة جديدة تنحرف")؛ Web Design Guidelines لقى أخطاء ما تبين في اللقطات؛ webapp-testing لقط تداخل في القائمة من الصورة. النصيحة: ابدأ بـ frontend-design + Interface Design + Web Design Guidelines، ومحرك أسلوب واحد فقط.
2. **تقرير بناء Jarvis** (20 أكتوبر، في `references-2026-10-20-morning.md`): الشكل "البسيط" ما يتحسّن باشتراك أغلى؛ الناجحون بدأوا من ريبو جاهز فيه الكرة المتوهجة، وأعطوا الذكاء الاصطناعي صوراً مرجعية وقواعد تصميم مكتوبة، وبنوا شاشة واحدة في كل مرة. واحد منهم استهلك حصته على Pro خلال ~15 دقيقة لأن Claude Code شغّل خمسة subagents من نفسه (نفس اللي صار مع أحمد).
3. **Mission Control** (أعلاه): الوكلاء يحتاجون أدوار وتعليمات و**بروتوكول تقرير** مكتوب، وإلا النتائج غير متسقة؛ حواجز (كشف الحلقات، حد التوازي) ضرورية للتشغيل الذاتي؛ ملف سياق مولّد (`ai-context.md`) يخلي الجلسة الجديدة تكمل بدون إعادة شرح.
4. **بناء مواقع Three.js سينمائية بـ Claude** (مقالات وفيديوهات 2026): الخيط المشترك: سكل 3D يعطي السياق (مشاهد، تفاعلات، قيود WebGL) بدل مقتطفات معزولة؛ مكتبات بقطع جاهزة (ThreeUI، React Bits)؛ إصدارات مثبّتة (r128/r170)؛ وبوابة حركة بـ Playwright قبل التسليم (auteur).
5. **Claude Code Agent Monitor وopcode**: ناس كثير بنوا "لوحة" فوق Claude Code نفسه عشان يشوفون الجلسات والوكلاء والتكلفة حية — يعني فكرة "غرفة العمليات ببيانات حقيقية" مجرّبة ومتاحة كمراجع مفتوحة المصدر.
