# مشروع جديد من الصفر — ثلاث بدايات، كل وحدة الأفضل في محورها (22 أكتوبر 2026، الصبح)

بطلب أحمد: "أريد بناء مشروع جديد من الصفر. ابحث في كل شي درسناه ونتائجه وأعطني ثلاث حلول، كل حل تعتبره الأفضل بمستوى واحد." هذا الملف يجمع النتائج أولاً، ثم ثلاث بدايات متساوية الوزن بدون ترتيب.

## النتائج اللي تدخل في أي بداية (من شهرين فعلياً)

**اللي اشتغل:** شريحة وحدة صغيرة بعقد مكتوب وآلة حالة وموافقة قبل الكتابة، اشتغلت من الجوال يوم 2 أكتوبر. إصلاحات صغيرة مختبرة (20 أكتوبر). هيكل Codex الصادق اللي يقول "غير متاح" بدل ما يدّعي.

**اللي فشل، ولماذا:** البداية من الشكل بدون عقل خلفه طلّعت تطبيقات "قديمة وبسيطة". البرومبت الواحد اللي يبني كل شي شغّل 80 وكيلاً وحرق الرصيد. عدة أدوات على عدة فروع بدون مالك ولا بوابة حذفت 30 اختباراً وما أحد لاحظ. النطاق تضخم كل أسبوع (صوت، مركبة، Unity، Unreal وشراء مشهد، خمسة مسارات) والمنتج الشغّال بقي شريحة 2 أكتوبر. الوثائق صارت أكثر من العروض الحية. وخلط السياق بين المحاولات القديمة والجديدة.

**ثوابت أحمد:** مب مبرمج ولا يستمتع بالكود؛ اللابتوب ما يقدر يبقى شغّالاً والإنترنت ينقطع؛ عربي عامي؛ الشكل أهم شي (ليل، أسود وذهبي، سينمائي، لا كواكب ولا شخصيات)؛ الشات في الوسط؛ لوحة حية بأسلوب n8n ببيانات حقيقية؛ يشوف ويوقف ويستأذن ويعرف التكلفة؛ الصوت خيار؛ وصول من الجوال.

**قواعد تدخل في البدايات الثلاث (هي اللي كانت ناقصة):**
1. ريبو جديد فاضي = سياق نظيف؛ المحاولات القديمة أرشيف خارجه.
2. أداة وحدة تكتب كوداً في الأسبوع؛ الباقي رأي.
3. CI من أول كومت (`test` + `typecheck` على كل PR) وحماية main: لا دفع مباشر من أحد.
4. عرض حي كل أسبوع على اللابتوب أو الجوال؛ أسبوع بدون عرض = ينقص النطاق.
5. تجميد النطاق 30 يوماً: ملف واحد اسمه SCOPE.md، أي فكرة جديدة تنكتب في IDEAS.md وما تدخل.
6. ممنوع "ابنِ كل شي بضغطة"؛ شاشة أو أداة وحدة في كل جلسة.

## البداية A — "وكيل دائم التشغيل بدون كود تقريباً"
**الأفضل في:** السرعة للوصول لوكيل يشتغل كل يوم، والتشغيل الدائم رغم اللابتوب والإنترنت.

- **الفكرة:** العقل وكيل جاهز على سيرفر صغير دائم (VPS بشهرية بسيطة): Hermes v0.22 بملف شخصي عربي، أو وكيل n8n، أو بوتاتك الموجودة على Grok Bot لو منصتهم تعطي بث أحداث وموافقات (يُتحقق). كل شي جاهز من اليوم الأول: الأدوات، الموافقات، الإيقاف، الجدولة، الذاكرة، الكونكترات، المتصفح الآمن، وبوابة الجوال (Telegram/WhatsApp).
- **الأسبوع الأول:** VPS + تثبيت + ملف شخصي عربي + Telegram من جوالك + ثلاث أدوات مسموحة فقط (بحث، ملفات على السيرفر، قراءة بريد) + موافقة إجبارية على أي كتابة. تستخدمه فعلياً من اليوم الثالث.
- **الريبو الجديد يحتوي:** `config/` (YAML/JSON للملف الشخصي والأدوات والصلاحيات)، `skills/` (مهارات بالعربي)، `bridge/` (~150 سطراً تقرأ الأحداث وترسل القرارات)، `world/` (صفحة ويب واحدة بالثيم الأسود/الذهبي تعرض الشات والسجل الحي وبطاقة الموافقة وزر الإيقاف والعداد). لا كور، لا قاعدة بيانات، لا تطبيق جوال.
- **الشكل:** في الأسبوع الأول الواجهة هي تطبيق Hermes المكتبي بثيمك + Telegram. من الأسبوع الثالث صفحة العالم الخفيفة تقرأ الأحداث؛ الجمال يجي بالتدريج بدون ما يوقف الاستخدام.
- **الجوال والتشغيل الدائم:** محلولان بطبيعة الحل (السيرفر شغّال 24 ساعة، والجوال عبر البوابة).
- **التكلفة:** VPS ~$5–12 شهرياً + استهلاك الموديلات. GPU غير مطلوب.
- **السقف:** الواجهة تبقى "لوحة" مب عالماً سينمائياً إلا لو انضاف لاحقاً فوق نفس الأحداث؛ وتعتمد على مشروع يتغير بسرعة (نثبّت إصداراً).

```yaml
# repo: ahmed-agent-cloud
config/profile.yaml:   { name: "أحمد", language: "ar", tone: "عامي", approvals: "all-writes", daily_budget_usd: 5 }
config/tools.yaml:     { include: ["web_search", "read_file", "email_read"], exclude: ["*delete*", "*payment*"] }
bridge/:               events_wait -> ws://world ; approval.decision -> permissions_respond ; kill -> /stop
world/index.html:      chat + live log + approval card + stop + cost (black/gold, RTL)
.github/workflows/ci.yml: test + typecheck on every PR
SCOPE.md:              "30 days: daily use via Telegram + one web page. Nothing else."
```

## البداية B — "كور صغير مملوك + لوحة حية، يكبر أداة كل أسبوع"
**الأفضل في:** التحكم والأمان والتقدم المتوقع؛ كل سطر ملكك والأسئلة الأربعة مجابة بالتصميم.

- **الفكرة:** إعادة بناء النمط اللي نجح (عقد → كور بآلة حالة وموافقة وتدقيق → عميل) بشكل أنحف، مع إصلاح العملية من أول يوم. العميل تطبيق ويب يُفتح من اللابتوب والجوال (PWA): الشات في الوسط، اللوحة الحية بأسلوب n8n (React Flow) ببيانات حقيقية من أحداث الكور، لوحات جانبية، بطاقة موافقة، زر إيقاف، عداد تكلفة، ثيم أسود/ذهبي، RTL.
- **الأسبوع الأول:** الكور بأداتين (قراءة ملف + نقل بموافقة) مع 40 اختباراً خضراء وCI، والعميل بشاشة وحدة: شات + بطاقة موافقة. عرض حي يوم الجمعة من الجوال.
- **بعدها أداة واحدة كل أسبوع** خلف السجل والموافقة: بحث ويب، قراءة بريد، تقويم، ملاحظات… واللوحة الحية تكبر مع الأدوات.
- **الشكل:** 2.5D مرتّب وفخم (عمق، توهج خفيف، نبضة على الخطوط، صوت واجهة) مب عالماً ثلاثي الأبعاد؛ الثيم ملف واحد يبدّل كل شي. المشهد السينمائي يصير "جلداً" لاحقاً فوق نفس الأحداث لو بغيت.
- **الجوال والتشغيل الدائم:** الكور على VPS صغير (نفس كود اللابتوب)، فيشتغل دائماً والجوال يفتحه كصفحة.
- **الريبو الجديد:** `packages/contract`، `apps/core`، `apps/web`، `.github/workflows/ci.yml`، `SCOPE.md`. بدون سكلز تصميم إلا 10–15 لازمة.
- **التكلفة:** VPS ~$5–12 شهرياً + الموديل. بدون GPU.
- **السقف:** الإبهار أقل من عالم 3D؛ ويحتاج إنك تقبل كوداً تكتبه أداة واحدة تحت بوابة، لأنك ما تبي تكتب بنفسك.

```yaml
# repo: ahmed-agent-v1
packages/contract:  AgentRequest / AgentResponse / TaskStatus / ApprovalRequest   (كما نجح في v0.1)
apps/core:          state machine + approvals + audit + tool registry (read_file, move_file) ; +1 tool/week
apps/web:           chat (center) + React Flow live board + side panels + approval card + stop + cost ; theme.json
deploy:             laptop now, VPS later (same build)
.github/workflows/ci.yml: npm ci && npm test && npm run typecheck   # required check on main
SCOPE.md:           "30 days: 4 tools, 1 screen, weekly demo. No voice, no 3D."
```

## البداية C — "المشهد أولاً: عالم سينمائي جاهز + وكيل عبر API"
**الأفضل في:** طموحك البصري: مكان تجلس فيه، سينمائي من أول يوم، وسقف تصميم عالٍ.

- **الفكرة:** الريبو يبدأ بمشهد جاهز قابل للتعديل (مقصورة/غرفة ليلية بزجاج وغيوم) نشتريه أو نأخذه مجاناً: Unreal + Fab لأعلى واقعية (يحتاج كرت شاشة قوي)، أو قالب Three.js/Spline متميز لو الكرت متوسط. الوكيل برا المشهد كـAPI (Hermes على سيرفر، أو وكيل n8n)، والمشهد يقرأ أحداثه عبر جسر صغير ويرسل الموافقات والإيقاف.
- **الأسبوع الأول:** فحص كرت الشاشة → اختيار مشهد واحد والموافقة على سعره → يشتغل على اللابتوب بشمس من ساعة الواقع وصوت جو. بدون وكيل بعد. لقطة شاشة = العرض الحي.
- **الأسبوع الثاني:** شاشة الشات داخل المشهد مربوطة بالوكيل الحقيقي. **الثالث:** النواة بسبع حالات والنبضة على الخط من أحداث حقيقية. **الرابع:** بطاقة الموافقة والإيقاف والعداد. بعدها يكبر مشهد واحد فقط لمدة 30 يوماً.
- **الشكل:** هو المنتج. الذوق مكتوب (ليل، ذهبي دافي، لا كواكب ولا شخصيات)، وقواعد الحدث → الشكل في ملف واحد يتعدل بدون كود.
- **الجوال والتشغيل الدائم:** الوكيل على السيرفر دائماً والجوال عبر بوابته؛ العالم على اللابتوب لما تفتحه (أو يُبث من السحابة لاحقاً بـPixel Streaming).
- **الريبو الجديد:** `scene/` (المشروع المشترى + تعديلاتنا فقط)، `bridge/`، `rules/events.json`، `docs/evidence/` (لقطة شاشة أسبوعية)، `SCOPE.md`.
- **التكلفة:** المشهد (مجاني إلى ~$50–200)، VPS للوكيل، وكرت شاشة لو Unreal.
- **السقف:** الأثقل تقنياً والأبطأ لأول استخدام يومي؛ يعتمد على الجهاز؛ وأعلى خطر انجراف نحو "الشكل قبل الوظيفة" لولا قاعدة الأسبوع الثاني (الشات الحقيقي).

```yaml
# repo: nexus-world
scene/:        purchased editable cabin scene (Unreal + Fab | premium Three.js template) ; ONE scene for 30 days
bridge/:       agent events (Hermes API / n8n) -> world ; approvals + stop back
rules/events.json: { "approval.requested": [...], "tool.failed": [...], "agent.started": [...] }
weekly:        W1 scene runs ; W2 real chat inside ; W3 core states + pulses ; W4 approval card + stop + cost
SCOPE.md:      "30 days: one scene, one screen, real agent by week 2. No second scene."
```
