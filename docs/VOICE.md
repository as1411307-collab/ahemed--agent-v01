# محادثة iPhone الصوتية — 9 أكتوبر 2026

الحالة: نُفّذ امتداد الصوت في المصدر، واجتازت الفحوص البرمجية. لم تُبنَ نسخة iPhone موقّعة ولم يُختبر صوت حي على جهاز أو اتصال بمزوّد فعلي. تعليمات النسخة الحالية موجودة هنا؛ وصف Expo Go القديم في تقرير 2 أكتوبر يخص تجربة النص والملفات.

## اختيار التكامل العملي

| المسار المدروس | الملاءمة للمستودع الحالي | القرار |
|---------------|-------------------------|--------|
| React Native WebRTC + OpenAI Realtime، مع تحكم من الخادم | مكتبة جاهزة للميكروفون ونقل الصوت وتشغيله، وVAD وتفريغ جاهزان؛ تُمرّر المدخلات إلى وكيل Anthropic الحالي من الـCore | المسار المنفّذ؛ أقل تغيير في التشغيل الحالي، دون خدمة تنسيق جديدة |
| LiveKit React Native + خدمة Agents | نقل وصوت جاهزان وإمكان تركيب pipeline من STT / الوكيل الحالي / TTS | صالح، لكنه يضيف غرفة اتصال وخدمة Agents وتكوينًا إضافيًا لهذا المستودع؛ لم يُنفّذ أو يُختبر |
| expo-audio مع تفريغ ثم TTS | مناسب لتسجيل مقاطع وتشغيلها | لا يحقق وحده محادثة مباشرة بمقاطعة وVAD؛ يحتاج إدارة مقاطع ومحرّك تدفق إضافيين، لذلك لم يُستخدم |

القرار يخص هذا المستودع ومتطلب الاحتفاظ بالوكيل الحالي، وليس ترتيبًا عامًا لكل المنصات. توصي OpenAI بـWebRTC للأجهزة المحمولة، وتدعم تهيئة الجلسة من الخادم عبر `/v1/realtime/calls` مع قناة تحكم جانبية. وجود هذه المكتبات لا يثبت نجاح البناء الأصلي على iPhone؛ هذا هو الاختبار المتبقي.

الحزم المثبّتة: `react-native-webrtc@124.0.8`، `@config-plugins/react-native-webrtc@15.0.2`، `expo-dev-client@57.0.19`، `expo-build-properties@57.0.22`، و`ws@8.22.0` في الخادم. نُقلت نسخ Expo من خريطة SDK 57 المثبّتة. شرط peer للمكوّن هو `expo >=56`؛ جدول README للناشر يقف عند SDK 56، ولذلك لا ندّعي اعتمادًا خاصًا لـ57 أو تحققًا أصليًا لم يُجر. نجح توليد إعدادات iOS وتجميع JavaScript بهذه النسخ.

## الربط بالوكيل الحالي

1. التطبيق يطلب إذن الميكروفون عند الضغط على «بدء الصوت» ويُنشئ عرض WebRTC.
2. يرسل العرض و`conversation_id` الحالي إلى Core API مع `APP_TOKEN`.
3. الـCore ينشئ جلسة المزوّد بمفتاحه، ثم يربط قناة التحكم قبل إعادة SDP إلى التطبيق. التطبيق لا يحصل حتى على مفتاح مزوّد مؤقت.
4. المزوّد يرسل تفريغ الكلام إلى الخادم. الـCore يمرّره عبر `Messages`، وهو نفس المسار للنص والملفات، إلى `Agent.processTask` وSQLite.
5. نموذج Anthropic الحالي يرى سجل المحادثة ومرفقاتها ويستخدم أدواته الموجودة. الصوت لا يملك أدوات أو صلاحية تنفيذ.
6. الخادم يطلب قراءة نتيجة الـCore صوتيًا. `create_response=false` و`interrupt_response=false` يمنعان رد المزوّد التلقائي. طلب القراءة يستخدم `conversation="none"` و`input=[]` دون سياق صوتي مستقل أو أدوات.
7. أي كتابة تبقى `WAITING_FOR_APPROVAL`. يظهر طلب الموافقة في البطاقة الحالية؛ كلمة «موافق» في الصوت لا تنفّذ قرارًا. الضغط على البطاقة يمر عبر نقطة القرار الأصلية، والتنفيذ والتحقق والتدقيق كما كانا.

القراءة الصوتية عبر نموذج Realtime موجّه لنطق النص؛ ليست ضمانًا حرفيًا من محرّك TTS حتمي. تُسجّل النسخة المنطوقة حين يرسلها المزوّد للتدقيق، وتبقى رسالة الـCore هي النتيجة المعتمدة. جودة العربية ووفاء الصوت للنص وتأخير التفريغ والوكيل تحتاج اختبارًا فعليًا. الصوت لا يتوسع في قدرات الوكيل: الأدوات الحالية ما زالت قراءة ملفات ونقلها بموافقة.

الكلام الجديد يوقف التوليد ويُفرّغ الصوت غير المشغّل. النتيجة المتأخرة تُحفظ في المحادثة، ويُمنع نطقها إذا تجاوزها كلام أحدث. التفريغ يُعالج بترتيب المقاطع، ولو اكتمل تفريغ المقطع الثاني قبل الأول. لكل مقطع معرّف طلب ثابت؛ الإعادة لا تنتج مهمة ثانية.

## واجهة الصوت

- بدء، كتم/تشغيل الميكروفون، وإنهاء المكالمة.
- مؤشر دائري ثنائي الأبعاد يتغير مع نشاط كلام المستخدم وتشغيل رد الوكيل، مع حالة معالجة الطلب. حركة نبض بسيطة من أحداث الحالة، وليست قياسًا لشدة الصوت ولا شخصية ثلاثية الأبعاد.
- دعم Reduce Motion وأزرار بحجم لمس مناسب ووصف للصوت المولّد بالذكاء الاصطناعي.
- تبقى بطاقات الموافقات وقائمة المهام متاحة. يُوقف الإدخال النصي والرفع أثناء المكالمة لمنع إرسال مدخلات متزامنة من هذه الواجهة.
- عند الإنهاء أو الخلفية أو فشل الاتصال تُحرر مسارات الصوت وPeerConnection. المهمة المقبولة بالفعل تستمر في الـCore. لا إعادة اتصال صامتة ولا إعادة إرسال للأمر.
- طلب إذن الميكروفون فقط؛ لا كاميرا ولا وضع تسجيل في الخلفية. يبدأ timeout التفريغ بعد تثبيت المقطع، مع حد انتظار يحمي الطابور.

## التشغيل الفعلي على iPhone

**Expo Go لا يتضمن WebRTC الأصلي. يلزم Development Build جديد.** يمكن أن تبقى المحادثة النصية والملفات على Expo Go بإصدار يدعم SDK 57؛ زر الصوت فيه يعرض السبب بدل تعطيل التطبيق.

| بيئتك | المتطلبات |
|-------|----------|
| Windows أو Linux، والبناء على EAS | حساب Expo/EAS وحساب Apple Developer للبناء الموقّع لجهاز، وتسجيل iPhone عند الطلب. لا يحتاج Xcode على Windows. لم يُطلق أي بناء أو اشتراك هنا. |
| Mac مع بناء محلي | Xcode وأدوات iOS وتوقيع Apple وربط الجهاز. هذا هو المسار الذي يتيح تجربة جهاز دون حساب Apple مدفوع، وفق وثائق Expo، مع قيود التوقيع المعتادة. |

اختير `com.ahmed.agent` كمعرّف أولي قابل للتعديل قبل التوقيع. إن كان التطبيق له معرّف معتمد في حسابك فاستعمله. أُضيف `ios.enableSceneSupport=true` لأن SDK 57 المبني باستخدام Xcode 27/iOS 27 SDK يحتاج دعم المشاهد؛ النسخة الحالية Expo 57.0.26 تتجاوز الحد المطلوب 57.0.23. نجح التحقق من manifest المُولّد؛ ذلك لا يعادل إطلاق التطبيق على iOS 27.

### الخادم

احتفظ بإعدادات Anthropic و`APP_TOKEN` الحالية. امتداد الصوت اختياري، ومُعطّل افتراضيًا حتى يُهيّأ المزوّد. عند تفعيله تكون هذه الإعدادات في بيئة الخادم `apps/core/.env` فقط:

```dotenv
VOICE_ENABLED=true
VOICE_MODEL=gpt-realtime-2.1
VOICE_TRANSCRIPTION_MODEL=gpt-4o-transcribe
VOICE_NAME=marin
```

يحتاج التشغيل كذلك `OPENAI_API_KEY` معتمدًا في الخادم. لم يُنشأ أو يُستخدم مفتاح في هذه الجلسة. لا تنقله إلى التطبيق أو Git أو متغيرات `EXPO_PUBLIC_*`. هذا ليس جزءًا من اشتراك ChatGPT؛ استخدام مزوّد الصوت والوكيل يُحسب حسب حسابات API عند التشغيل.

من جذر المستودع:

```powershell
npm ci
npm run core
```

في التطبيق تبقى القيمتان الموجودتان فقط: `EXPO_PUBLIC_CORE_URL` و`EXPO_PUBLIC_APP_TOKEN`. على شبكة محلية استخدم IP الكمبيوتر وليس `localhost`، واجعل الكمبيوتر وiPhone على نفس الواي فاي، واسمح لـNode على الشبكة الخاصة. يلزم وصول الإنترنت لمزوّد الصوت والوكيل، وإذن الميكروفون والشبكة المحلية على iPhone. للوصول عبر الإنترنت استخدم Core عبر HTTPS.

### بناء سحابي من Windows

من جذر المستودع بعد التثبيت، شغّل الأوامر التالية في نافذة أخرى. نسخة EAS CLI التي تحققنا من توفرها هي 24.12.1؛ هذه الأوامر لم تُنفّذ هنا لأنها تتطلب حسابك وتوقيع Apple:

```powershell
Set-Location apps/mobile
npx eas-cli@24.12.1 login
npx eas-cli@24.12.1 build --platform ios --profile development
```

اتبع إعداد حساب Expo/المشروع وتوقيع Apple وتسجيل جهازك في EAS. ثبّت النسخة من رابط البناء، وفعّل Developer Mode إن طلبه iPhone. ثم من جذر المستودع:

```powershell
npm run mobile:voice
```

افتح Development Build وامسح رمز QR. إعادة بناء النسخة مطلوبة عند تغيير الحزم الأصلية أو إعدادات plugins. Metro مطلوب لتجربة Development Build؛ لا يُدّعى أن هذه نسخة توزيع مستقلة أو App Store أو TestFlight.

### بناء محلي على Mac

بعد تجهيز Xcode والتوقيع وربط iPhone، من جذر المستودع:

```sh
npm run ios -w @ahmed/mobile
```

هذا يولّد المشروع الأصلي ويثبّت الحزم الأصلية ويبدأ بناء الجهاز في بيئتك. لم يُنفّذ هنا.

الفحوص تغطي المصادقة، والتحقق من SDP، وتكرار التفريغ، وترتيب المقاطع، واستمرار سياق الملفات، والموافقة والرفض والانتهاء والتنفيذ مرة واحدة، والمقاطعة، والنتيجة المتأخرة، وإغلاق جلسة بعيدة عند فشل قناة التحكم، وتحرير الميكروفون أثناء سباق الإنهاء/بدء الاتصال. المهام والأدوات الأصلية اجتازت اختبارات الانحدار كلها.

### اختبار القبول على الجهاز (المتبقي)

1. افتح النسخة الموقّعة، وارفع `notes.txt` في نفس المحادثة، ثم ابدأ الصوت وامنح إذن الميكروفون والشبكة.
2. قل: «لخّص الملف». تحقق من دخول نص الطلب في نفس المحادثة وظهور المهمة وسماع نتيجة الوكيل الحالي، ومن وقت التأخير وفهم العربية.
3. قل: «انقل الملف إلى archive». يجب أن تظهر بطاقة موافقة وألا يتحرك الملف. جرّب قول «موافق» وتأكد أنه لا يوافق تلقائيًا، ثم ارفض من البطاقة.
4. أعد طلب النقل ثم اضغط موافق مرتين. تحقق من نقل واحد وعلامة التحقق وسجل القرار والتنفيذ؛ كرر بموافقة منتهية للتأكد من عدم التنفيذ.
5. قاطع الرد بكلام جديد. يجب أن ينقطع الصوت السابق وتتغير الحالة البصرية، وتبقى المهمة القديمة في السجل.
6. جرّب كتم الميكروفون، الإنهاء أثناء الاتصال وأثناء المعالجة، رفض إذن الميكروفون، قطع الواي فاي/الإنترنت، إطفاء الشاشة والخلفية. تحقق من اختفاء مؤشر الميكروفون واستعادة المحادثة والمهام.
7. اختبر سماعة الهاتف وBluetooth/Speaker، الصدى، Reduce Motion، وإعادة بدء مكالمة بعد انقطاع الـCore. لا تُعتمد جودة المسار الصوتي قبل هذه التجربة.
